# 東京近郊の非格子街区・ローカル改修

基点は `957918a2a7f4eec9d80f392bb3fb801935ec0b7b`（`claude/sharp-cori-gozebu`、v0.5.0）。作業ブランチは `codex/tokyo-organic-neighborhood`。旧作業場所の `codex/glb-visual-pilot` と、既存498種・23 GLBパックは変更していない。push・公開は行っていない。

## 確認方法

```powershell
npm ci --ignore-scripts
npm run dev -- --host 127.0.0.1
npm run test:neighborhood
npm run benchmark:neighborhood
npm run capture:neighborhood
npm run build
```

テストはインストール済みのPC版Chromeを `playwright-core` で起動する。別のChrome実行ファイルを使う場合は `CHROMIUM_PATH` に絶対パスを設定する。localhostのViteサーバーは各検証スクリプトが起動・終了する。

| URLクエリ | 内容 |
|---|---|
| なし | 約400m四方の改修街区 |
| `?district=pilot` | 最初に検証した約100mの通りと実際に再合流する迂回路 |
| `?streetscape=sample` | 敷地密度を先に確認した住宅路garden-slope・商業路west-shoppingの部分適用 |
| `?layout=legacy` | 旧7×7街区の比較用表示 |

ブラウザコンソールの `window.__game().city.roads` に中心線サンプルと接続グラフ、`.parcels` に配置した敷地データがある。

## 道路・敷地

`src/data/neighborhood.ts` が中心線の接続点・通過点・幅・標高の正本。Catmull–Rom曲線を約1.5m間隔でサンプルし、道路・歩道・排水帯・公園路を生成する。区画ごとの舗装箱は使わない。

- 41本、25接続点、道路・園路の合計約3,260m。主街路8m、住宅路4.5～6m、細い路地3.2～3.5m、公園路2.6～3m。
- 道路標高は−0.4～8.3m。最大中心線勾配は約9.9%。各接続点は同じ標高を共有する。
- 最初の通りは103.35m。主街路2区間を除外しても184.09mの迂回路が再合流する。公園の3入口、緑道、南側のずれた丁字路、北側の尾根・団地が長短のループを作る。
- 284敷地。戸建て196、小アパート・マンション29、団地11、商店39、会社4、ゲームセンター1、小駐車場4。これは建物数とは異なる。実装上の `buildings` は塀・柵も含む。
- 代表の住宅路を2→6敷地、商業路を5→8敷地にして地上描画と移動を確認してから全域へ展開。建物幅に足していた余白と敷地間隔を縮め、前庭・駐車・裏庭の寸法を用途で変える。店舗は歩道へ寄せ、背後と脇の通路を分ける。
- 任意角度の敷地を道路全サンプルと照合し、道路・公園路を塞ぐ配置を除く。塀処理はGLB配置と独立。玄関口2.2m、住宅の車両口3.5m、小駐車場5.4mを基本とし、歩道の分割点・切下げ・塀開口が同じ入口寸法を使う。
- 歩道は帯状。車両出入口は歩道・縁石を開け、中心線の標高から個別敷地へスロープでつなぐ。4区画の小駐車場には駐車枠、車、塀、出入口を持たせる。電柱は開口を避ける。
- 既存 `infra_043` を路端・出入口の格子蓋、`048–050` を公園柵、`057` を車止め、`093` を段差がある敷地の擁壁に使用。直線用 `036–038` の舗装箱は曲線へ重ねず、連続縁石・切下げ・歩道を共通地形メッシュで作る。
- 屋根・壁付設備は各GLBの固有形状を保持する。外接箱を壁面だと仮定して雨樋や室外機を重ねない。草は壁際・排水桝周辺、樹木は公園・緑道・背割りの空地へ置く。
- 敷地全面の芝をやめ、前面・脇通路・駐車を舗装し、草は小さな前庭と裏庭に限定。既存の駐輪ラック・自転車・ごみケージ・防鳥ネット・プランター・菜園花壇を用途に応じて配置する。
- 街区内部の4か所を菜園・児童広場・休憩庭として区切り、各2本の接続路を用意。敷地を避けて経路探索し、見通せる区間で簡約する。入口は12m以上離し、内部で同じ経路に重ならない。道の描画・接地・Havokを共通化し、8経路を通常のプレイヤー移動で検証した。主道路41本の中心線・接続は変更していない。

## 地形と衝突

`Terrain.ts` の同じ三角形を描画、`heightAt`、射線、Havok `PhysicsShapeMesh` に使用する。縁石の立面も射線・Havokに入る。旧版のy=0衝突平面は改修街区には置かない。

建物は広域検索用AABBと、任意角度の狭域OBBを併用する。円形移動、射線、範囲攻撃、高さ判定を建物のローカル座標で評価する。倒壊・粉塵・残骸は敷地の `baseY` を保持する。

プレイヤー開始位置・起き上がり・カメラの最低高度、地上敵の落下着地と分離後の接地を修正。アイテムは既存の高さコールバックを共通地形へ接続した。

新アパートは本体、地上ポーチ、外側アプローチ、16段の階段、2階共用廊下を個別の衝突箱で表す。ゲームセンターは庇下と奥まった入口を開ける。住戸内装は対象外。既存GLBの多くは従来と同様に簡略化した外形衝突で、全窓・雨樋・枝葉の精密コリジョンを追加したわけではない。

## 実機測定

2026-10-16、同じPCのChrome 155.0.8059.82、Intel Iris Plus / ANGLE D3D11、1280×720、画質low、seed726146。12描画をウォームアップ後、60描画を採取。ゲーム更新を停止した固定カメラで `scene.render()` のCPU側経過時間とdraw callsを測定した。GPUタイマーや戦闘中の総フレーム時間ではない。

| 固定視点 | 元版 median / P95 | 初回162敷地試作 median / P95 | draw calls 元版→初回 |
|---|---:|---:|---:|
| 地上 | 139.2 / 264.1 ms | 25.8 / 38.2 ms | 1,703 → 475 |
| 俯瞰 | 79.0 / 101.8 ms | 28.2 / 35.3 ms | 1,308 → 554 |

地上カメラXZ=(0,6)、目線2.1m、注視点(-22,3,-35)。改修後は足元の地形標高を目線へ加算。俯瞰は(260,290,285)→(0,1,0)。比較用の霧・遠平面・画質は同じ。

最終284敷地版の測定を2回実施した。draw callsは一致した一方、CPU時間には大きなばらつきがある。PCの他負荷・電力・温度などを統制できていないため原因は断定せず、都合のよい回だけを比較値として採用しない。

| 固定視点 | 最終A median / P95 | 最終B median / P95 | 最終draw calls / 元版比 |
|---|---:|---:|---:|
| 地上 | 82.4 / 143.2 ms | 103.7 / 144.8 ms | 598 / 約65%減 |
| 俯瞰 | 130.0 / 210.4 ms | 100.9 / 131.2 ms | 499 / 約62%減 |

直前の小設備距離制限なし版は地上39.8ms・603 calls、俯瞰37.8ms・519 callsだった。この時間差を距離制限の効果とは扱わない。最終版の有効三角形は地上220,683、俯瞰276,151。起動は最終A48.6秒、B67.2秒（元版59.4秒、初回試作16.9秒）で、これもコールド起動を統制した比較ではない。安定した速度改善・60fps維持は未確認。

境界メッシュと道路面を材質・96m区画単位に結合。塀の個別OBBとHavokボディは保持する。GLBは共有材質とインスタンス、近景/中景/遠景LODを使う。駐輪・ごみ容器・小プランター・排水蓋は85mで表示を止め、建物と破壊対象にはその制限を適用しない。小設備と電線の距離LOD、塀・細部の影の除外、通常画質の建物影95m以内の制限を併用。総mesh数18,970、material数1,081は未使用テンプレート・材質も含み、実際のdraw callsとは区別する。

スマホ、高画質、GPU実行時間、消費電力、長時間・全ウェーブ戦闘の性能は未測定。今回の数値から60fps維持を保証しない。

## 検証と画像

PCの正式computer-use入口は調査したが、Windowsプラットフォームディレクトリを取得できず起動不可だった。既存の開発用 `playwright-core` とインストール済みChromeを使い、実際のBabylon/Havokを描画して検証した。CPUの画像生成や模式図を実機描画として扱っていない。

- `artifacts/neighborhood/pilot-first-tests/report.json`：先に完成させた100m試作の検証記録。`pilot-tests/report.json` は最終コードで100mモードを再検証した記録（2回ともPASS）。
- `artifacts/neighborhood/tests/report.json`：固定1/60秒、2回の新規ページで同一入力を再生。全41道路・路地の実移動、道路中心の通行可否、地形/射線/Havok、任意角度の壁、切下げと駐車出入口、外階段、敵とアイテムの接地、プレイヤー起き上がり、射撃による敵撃破、爆発による倒壊と残骸高を確認。
- 420フレームの入力列で移動2軸、射撃、照準、ズーム、ダッシュ、ジャンプ、回避、切替、装填を重ね、位置・状態・弾数のトレースを比較。
- `artifacts/neighborhood/before/metrics.json` と `after/metrics.json`：測定原本。
- `streetscape-final-benchmark/metrics.json`、`streetscape-repeat-benchmark/metrics.json`：最終284敷地版の測定A/B。`streetscape-benchmark/metrics.json` は小設備距離制限を加える前の記録。
- `artifacts/neighborhood/review/`：地上、入口、駐車場、公園、坂、ゲームセンター、アパート、団地、俯瞰のPNGとカメラ情報。
- `artifacts/neighborhood/streetscape-reviewed/`：最終版の18視点。`streetscape-pilot-tests/report.json`：密度修正後の100mモードも2回ともPASS。

初回の `review/overview.png` は霧を0.0004、遠平面を1400mにして全街区を表示した。最新の `streetscape-reviewed/` は建築確認用として敵と遠景アンカーを隠し、遠平面を1400mにする（地上の霧は通常のlow設定）。ゲーム本体は変更しない。どちらも負荷比較用カメラとは異なり、性能測定は `benchmark-neighborhood.mjs` で敵・遠景を含む従来条件を使う。カメラ・確認設定は `layout.json` に記録。検証成果はローカル生成物であり、再生成できるスクリプトをgitで管理する。

密度修正版：`streetscape-verified/report.json` で22項目×2回とも全検証PASS、420フレームの入力トレース一致、ブラウザ例外0。道路290点で高さと射線の最大差は浮動小数点誤差内、Havokとの差は最大約5.1mm。全41道路を31,538更新フレームで歩行し、25敷地の入口へ通行。共同利用地の8経路も通過した。

車両入口70か所は、左右の車輪位置と中央の3断面を5cm刻みで調べ、最大高低差6.13mm、Havokとの差は最大8.38mm。幅3.5m/5.4mで縁石と歩道の開口を合わせた。これは車両入口の幾何・物理面の検証であり、未実装の運転ゲームプレイの試験ではない。

外階段から2階廊下へ到達。敵・アイテムの接地、起き上がり、射撃・敵撃破、爆発・倒壊・残骸高も成功。25接続点は単一ネットワークで、主道路の独立ループは17（`network-audit.json`）。`streetscape-sample-2/` に先に確認した代表通り、`streetscape-before/` に密度修正前の画像を保持する。
